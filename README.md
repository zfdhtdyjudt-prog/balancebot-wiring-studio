## 1. ملخص سريع

**BalanceBot Wiring Studio** هو محرر دوائر محلي خاص بمشروع روبوت توازن/عربة روبوتية متعددة الأوضاع.

الموقع يتيح لك:

- اختيار أحد ثلاثة أوضاع للمشروع.
- رؤية المكونات في Canvas بصيغة SVG.
- رؤية أسماء الأطراف الفعلية على اللوحات والمكونات.
- إنشاء أسلاك بين أطراف محددة بالضغط على الطرف الأول ثم الطرف الثاني.
- تحرير المشروع مباشرة بصيغة JSON.
- فحص أن كل طرف في الأسلاك موجود فعليًا في سجل المكونات.
- عرض معلومات الطرف ووظيفته واتجاهه واتصالاته.
- البحث داخل مكتبة المكونات.
- إضافة مكونات من المكتبة بالنقر أو السحب والإفلات.
- استيراد مكوّن مخصص من ملف JSON.
- حفظ المشروع بصيغة JSON.
- تصدير الرسم إلى SVG.
- طباعة الرسم أو حفظه PDF من نافذة الطباعة في المتصفح.
- تشغيل عرض محاكاة منطقية/بصرية مبسطة لحالة الطاقة والمحركات وMPU6050.
- استخدام Firmware حقيقي منفصل للـArduino Uno والـESP32.
- استخدام Python Bridge لإرسال أوامر الحركة عبر Serial أو Wi‑Fi.

**الموقع ليس بديلًا عن القياس الكهربائي، ولا يحاكي تنفيذ تعليمات المتحكم أو الدوائر التناظرية أو فيزياء المحركات حاليًا.**

## 2. ما هو الموقع؟

الموقع عبارة عن تطبيق ويب ثابت Static Web Application يعمل من ملفات محلية، ولا يحتاج إلى خادم Backend أو قاعدة بيانات أو حساب مستخدم لكي يعمل.

يتكون من أربع طبقات رئيسية:

### 2.1 طبقة الواجهة

موجودة في:

- `index.html`
- `styles.css`

وهي مسؤولة عن:

- الهيكل RTL العربي.
- شريط الأزرار.
- تبويبات أوضاع التشغيل.
- مكتبة المكونات.
- محرر JSON.
- Canvas الرسم.
- لوحة الفحص.
- لوحة PINOUT.
- لوحة المحاكاة البصرية.

### 2.2 طبقة المنطق

موجودة في:

- `app.js`

وهي مسؤولة عن:

- تحميل `components.json`.
- تحميل العينات المضمنة.
- تحليل JSON.
- التحقق من المكونات والأسلاك.
- رسم SVG.
- حساب مواضع الأطراف.
- اختيار الطرف الأول والثاني.
- إنشاء الأسلاك.
- رسم المسارات المتعامدة.
- إدارة التكبير والشبكة.
- الاستيراد والتصدير.
- المحاكاة البصرية.
- حفظ المكونات المخصصة في `localStorage`.

### 2.3 طبقة البيانات

موجودة في:

- `components.json`
- `samples/*.json`
- `schema/project.schema.json`

وهي مصدر أسماء المكونات والأطراف والمواقع والأسلاك والإعدادات.

### 2.4 طبقة العتاد الحقيقي

موجودة في:

- `firmware/arduino_uno_robot.cpp`
- `firmware/esp32_robot.cpp`
- `firmware/unified_robot.cpp`
- `tools/bridge.py`

وهذه الطبقة ليست محاكاة داخل المتصفح؛ إنها Source Code يمكن رفعه إلى اللوحات الحقيقية بعد مراجعة الدائرة والجهود والمكونات فعليًا.

## 3. الإجابة المباشرة: هل هو Wokwi؟

### الإجابة المختصرة

**لا، الموقع ليس Wokwi كاملًا، ولا ينبغي وصفه بأنه نسخة مطابقة من Wokwi.**

لكنه يشبه Wokwi في جزء مهم من تجربة العمل، وهو:

- وجود مكتبة مكونات.
- وجود Canvas للتوصيل.
- وجود أطراف قابلة للاختيار.
- إنشاء الأسلاك من طرف إلى طرف.
- عرض أسماء الأطراف.
- وجود أمثلة جاهزة.
- وجود فحص أولي للأخطاء.
- وجود وضع تشغيل ومحاكاة بصرية.

### مستوى الشبه التقريبي

| المجال | مستوى الشبه الحالي |
|---|---:|
| مكتبة مكونات وواجهة مختبر | مرتفع نسبيًا |
| عرض أسماء الأطراف | مرتفع |
| رسم الأسلاك | مرتفع كمحرر تخطيطي |
| تحرير JSON | ميزة إضافية واضحة |
| فحص مراجع الأطراف | موجود وأساسي |
| تشغيل Firmware داخل المتصفح | غير موجود حاليًا |
| محاكاة كهربائية حقيقية | غير موجودة حاليًا |
| محاكاة فيزيائية للمحركات والعجلات | غير موجودة حاليًا |
| Debugger للمتحكم | غير موجود |
| مكتبات Arduino قابلة للبناء داخل الموقع | غير موجودة |
| محاكاة GPIO زمنية حقيقية | غير موجودة |
| PCB/Gerber حقيقي | غير موجود |
| تعاون سحابي متعدد المستخدمين | غير موجود |

إذن الوصف الأدق هو:

> **BalanceBot Wiring Studio هو محرر توصيلات وتعريفات دوائر Pin-Aware مع فحص منطقي ومحاكاة واجهة مبسطة، وليس محاكي MCU/كهرباء/فيزياء كاملًا.**

## 4. الفرق بين المحرر والمحاكي

### 4.1 المحرر

المحرر يتعامل مع سؤال:

> ما المكونات الموجودة؟ وما الطرف الموصول بالطرف الآخر؟ وأين تظهر على الرسم؟

المحرر يستطيع:

- إضافة مكونات.
- تغيير JSON.
- إنشاء أسلاك.
- إظهار أسماء الأطراف.
- اكتشاف endpoint غير معروف.
- تغيير المواضع في ملف المشروع.
- حفظ الرسم ومشاركته كبيانات.

### 4.2 المحاكي الحقيقي

المحاكي الحقيقي يجب أن يتعامل مع أسئلة مثل:

- ما قيمة الجهد على كل عقدة في كل لحظة؟
- هل هناك قصر؟
- ما التيار المار في المقاومة؟
- هل خرج GPIO يقود خرجًا آخر؟
- كيف تتغير قراءة HC-SR04 عند تحرك جسم؟
- كيف يتصرف PWM فعليًا؟
- كيف تتحرك العجلة وفق العزم والاحتكاك والكتلة؟
- كيف ينفذ المتحكم كل تعليمة في Firmware؟
- هل المكتبة المستخدمة في Arduino موجودة وقابلة للبناء؟

هذه الطبقة غير موجودة في الإصدار الحالي.

### 4.3 معنى زر "تشغيل المحاكاة"

زر `تشغيل المحاكاة` لا يشغل Firmware حقيقيًا ولا ينشئ دائرة كهربائية رقمية كاملة.

هو يعرض حالة بصرية تجريبية:

- يغيّر الحالة إلى `يعمل`.
- يعرض جهدًا منطقيًا افتراضيًا.
- يعرض PWM تجريبيًا للمحركات.
- يشغل مؤشرات المحركات.
- يعرض قراءة ميل افتراضية تتغير عشوائيًا كل فترة.
- يفعّل مؤشرات MPU6050 البصرية.

هذه الوظيفة مفيدة لاختبار تجربة الواجهة، لكنها ليست دليلًا على أن الدائرة الحقيقية ستعمل.

## 5. ما الذي تستطيع فعله من الموقع؟

### 5.1 بدء مشروع من عينة

عند فتح الموقع، تُحمّل عينة Arduino Only افتراضيًا.

يمكنك الانتقال إلى:

- Arduino Only.
- Hybrid Arduino + ESP32.
- ESP32 Standalone.

عند اختيار تبويب، يُستبدل المشروع الحالي بعينة الوضع المختار، ويُعاد رسم Canvas، ويُعاد فحص JSON.

### 5.2 قراءة الرسم دون لمس JSON

يمكنك فهم الرسم عبر:

- اسم المكوّن.
- أسماء الأطراف بجوار نقاط التوصيل.
- لون السلك.
- نوع الإشارة.
- لوحة PINOUT بعد اختيار المكوّن أو الطرف.
- لوحة الفحص الكهربائي.
- عداد المكونات.
- عداد الأسلاك.
- حالة المشروع.

### 5.3 تعديل المشروع يدويًا

محرر JSON هو مصدر الحقيقة داخل الموقع.

عند تعديل النص:

1. يتم تحديث أرقام الأسطر.
2. إذا كان `تحديث تلقائي` مفعّلًا، يعاد التحليل والرسم تلقائيًا.
3. عند وجود خطأ، تظهر رسالة في صندوق الخطأ.
4. عند نجاح التحليل، تُحدّث اللوحة والرسم والفحص.

### 5.4 إضافة مكوّن من المكتبة

يمكنك:

- البحث باسم المكوّن أو فئته.
- النقر على المكوّن لإضافته.
- سحب المكوّن إلى Canvas وإفلاته.
- استعمال المكوّن المضاف داخل JSON وإنشاء أسلاك له.

المكوّن الجديد يحصل على معرف جديد من نوع:

```text
component_new_1234
```

ويأخذ موضعًا ابتدائيًا داخل Canvas.

### 5.5 إضافة مكوّن مخصص

يمكن تحميل ملف JSON يصف مكوّنًا جديدًا، بشرط أن يحتوي على:

- `id`
- `name`
- `pins` كمصفوفة

ويُضاف له تلقائيًا بادئة `custom_` إذا لم تكن موجودة.

المكونات المخصصة تحفظ في Local Storage باسم:

```text
balancebot-custom-components
```

وهذا يعني أنها محفوظة في متصفحك الحالي، وليست مرفوعة تلقائيًا إلى GitHub أو قاعدة بيانات عامة.

## 6. طريقة تشغيل الموقع

### 6.1 التشغيل بواسطة السكربت

من جذر المشروع:

```bash
./start-local.sh
```

ثم افتح:

```text
http://127.0.0.1:4173
```

### 6.2 التشغيل بواسطة Python

```bash
python3 -m http.server 4173 --bind 0.0.0.0
```

ثم افتح:

```text
http://127.0.0.1:4173/index.html
```

### 6.3 لماذا لا يُفضّل فتح index.html مباشرة؟

لأن التطبيق يستخدم:

```javascript
fetch('components.json')
```

وبعض المتصفحات تمنع `fetch` من `file://` لأسباب أمنية. لذلك يجب استخدام static server بسيط.

## 7. شرح الواجهة قسمًا قسمًا

### 7.1 الشريط العلوي

يحتوي على:

- اسم BalanceBot Wiring Studio.
- وصف أنه محرر دوائر محلي قائم على JSON.
- زر `فتح JSON`.
- زر `حفظ JSON`.
- زر `تصدير SVG`.
- زر `تصدير PDF`.
- زر `تشغيل المحاكاة`.

### 7.2 منطقة العنوان والإحصاءات

تعرض:

- عنوان المشروع الحالي.
- شرح أن الأطراف بأسماء حقيقية.
- عدد المكونات.
- عدد الأسلاك.
- الحالة العامة مثل `جاهز`.

### 7.3 تبويبات الأوضاع

كل تبويب يغيّر العينة النشطة:

| التبويب | المقصود |
|---|---|
| Arduino Only | Arduino Uno يملك الحساسات والمحركات |
| Hybrid Arduino + ESP32 | ESP32 يستقبل الاتصال وArduino يملك المنظومة الرئيسية |
| ESP32 Standalone | ESP32 يملك المكونات مباشرة |

### 7.4 مكتبة المكونات

تعرض المكونات القادمة من `components.json` والمكونات المخصصة المحفوظة محليًا.

كل عنصر يعرض:

- الاسم.
- الفئة.
- الجهد المعلن.
- رمزًا بصريًا تقريبيًا.

### 7.5 البحث

البحث يطابق النص داخل:

- اسم المكوّن.
- اسم الفئة.

مثلًا:

```text
sensor
motor
Arduino
ESP32
Protection
```

### 7.6 محرر JSON

يحتوي على:

- أرقام أسطر.
- نص المشروع.
- تحديث تلقائي.
- زر عينة جديدة.
- زر رسم + فحص.
- صندوق أخطاء.

### 7.7 Canvas

يعرض:

- المكونات.
- أجسامًا SVG تقريبية.
- نقاط الأطراف.
- أسماء الأطراف.
- الأسلاك.
- ألوان الإشارات.
- تسميات الأسلاك.
- مسارات متعامدة.
- شبكة اختيارية.

### 7.8 لوحة الفحص الكهربائي

تعرض التحذيرات أو الأخطاء الناتجة من قواعد الفحص الموجودة في JavaScript، مثل:

- endpoint غير موجود.
- مكوّن غير معروف.
- أطراف غير متطابقة مع registry.
- بعض تحذيرات الجهد أو الاتجاه حسب البيانات المتاحة.

### 7.9 لوحة PINOUT

عند اختيار مكوّن أو طرف تظهر معلومات مثل:

- اسم الطرف.
- نوعه.
- اتجاهه.
- وظيفته.
- المكونات المتصلة به.
- اسم الطرف المقابل.

### 7.10 لوحة المحاكاة

تعرض:

- الطاقة.
- منطق التحكم.
- المحركات.
- MPU6050/IMU.
- مؤشرات تقدّم بصرية.

مرة أخرى، هذه لوحة حالة واجهة وليست محرك فيزياء.

## 8. أوضاع المشروع الثلاثة

## 8.1 Arduino Only

في هذا الوضع:

- Arduino Uno هو المتحكم الرئيسي.
- L298N يقود المحركين.
- HC-SR04 موصول إلى Arduino.
- MPU6050 موصول إلى Arduino عبر I²C.
- Potentiometer موصول إلى مدخل Analog.
- Passive Buzzer موصول إلى PWM.
- LEDs وIR موصولة إلى الأطراف المحددة.
- الاتصال الأساسي مع الحاسوب يكون عبر USB/Serial.

ملف العينة:

```text
samples/arduino-only.json
```

### 8.1.1 Arduino Only لا يستخدم ESP32

وجود ESP32 في مكتبة المشروع لا يعني أنه جزء من هذه العينة. هذه العينة تعرض Arduino فقط.

## 8.2 Hybrid Arduino + ESP32

في هذا الوضع:

- Arduino يملك المحركات.
- Arduino يملك MPU6050.
- Arduino يملك HC-SR04.
- Arduino يملك البازر.
- ESP32 يستقبل أوامر Bluetooth/Wi‑Fi.
- ESP32 يمرر الأوامر إلى Arduino عبر UART.
- خط TX من Arduino يحتاج تحويل مستوى إلى ESP32.

ملف العينة:

```text
samples/hybrid-arduino-esp32.json
```

## 9. طريقة إنشاء سلك بين طرفين

### الخطوات

1. اختر تبويب الوضع المطلوب.
2. ابحث عن المكوّن في Canvas.
3. اضغط على نقطة الطرف أو اسمه.

5. اضغط على طرف النهاية.
6. ينشأ السلك بين الطرفين.
7. يعاد الرسم والفحص.
8. تظهر معلومات الاتصال في PINOUT.

### معنى النقطة والاسم

كل طرف يظهر على الشكل باعتباره:

```text
نقطة اتصال + اسم الطرف
```

```text
Arduino Uno: ~5

```

الاتصال بينهما يعني:

```text
arduino_1.~5 → driver_1.ENA
```

يمكن إنشاء السلك مباشرة في مصفوفة `wires`:

```json
{
  "from": "arduino_1.~5",
  "to": "driver_1.ENA",
  "label": "left PWM",
  "signal": "control",
  "color": "control"
}
```

### قيود مهمة

- يجب أن يكون معرف المكوّن موجودًا في `components`.
- يجب أن يكون اسم الطرف موجودًا في `components.json`.
- يجب أن تكون الصيغة `componentId.pinName`.
- وجود سلك صحيح لغويًا لا يعني أن الاتصال آمن كهربائيًا.

## 14. الطاقة والحماية

### 14.1 بطارية 3S

| الحالة | الجهد |
|---|---:|
| حد التفريغ المحافظ | 9.6V |
| الجهد الاسمي | 11.1V |
| الشحن الكامل | 12.6V |

### 14.2 مسار الطاقة

```text
Battery B+
  → Main Power Switch IN
  → Main Power Switch OUT
  → L298N VMS/12V

Battery B-
  → L298N GND
```

### 14.3 تغذية المنطق

حسب التصميم الموثق:

```text
L298N 5V → Arduino 5V
L298N 5V → ESP32 VIN
```

لكن يجب التحقق من:

- وجود Jumper منظم 5V في L298N.
- قدرة المنظم على تغذية اللوحات والحساسات.
- حرارة المنظم.
- عدم إدخال 12.6V إلى ESP32 مباشرة.
- عدم إدخال 5V إلى ESP32 `3V3`.

### 14.4 Voltage Divider لـHC-SR04

لأن Echo في HC-SR04 قد يكون 5V، يستخدم التصميم:

```text
HC-SR04 ECHO ── R1=1kΩ ──●── ESP32 GPIO17
                           │
                         R2=2kΩ
                           │
                          GND
```

الناتج يقارب ثلثي الجهد الداخل، وهو أقرب إلى مستوى 3.3V من 5V.

### 14.5 LEDs

كل LED يحتاج مقاومة على التوالي:

```text
GPIO → 220Ω أو 330Ω → LED Anode
LED Cathode → GND
```

### 14.6 المحركات

- L298N هو Driver المحركات.
- لا توصل محرك TT مباشرة إلى GPIO.
- مخارج المحرك هي `OUT1` إلى `OUT4`.
- يجب مراجعة اتجاهات المحرك الفعلية لأن `M+` و`M-` قد يختلفان حسب التركيب.

2. اختر `Print to PDF` أو ما يعادلها.

### 23.5 Gerber

- قواعد DRC.

## 27. الوضع Hybrid وتعارض GPIO16/17

هذه نقطة مهمة جدًا.

الجدول يستخدم:

### Hybrid

```text
ESP32 GPIO17 → Arduino RX←0
Arduino TX→1 → Level Shifter → ESP32 GPIO16
```

### ESP32 Standalone

```text
HC-SR04 TRIG → ESP32 GPIO16
Voltage Divider OUT → ESP32 GPIO17
```

لا يمكن تنفيذ الوظيفتين على الطرفين نفسيهما في اللحظة نفسها دون تصميم إضافي.

لذلك:

- `BALANCEBOT_HYBRID_MODE=0`: يقرأ HC-SR04.
- `BALANCEBOT_HYBRID_MODE=1`: يفعّل UART2 ويعتبر HC-SR04 تابعًا لـArduino.

هذه ليست مجرد تسمية في الرسم؛ إنها ضرورة لمنع تعارض موارد GPIO في Firmware الحقيقي.

## 31. استكشاف الأخطاء

### المشكلة: الصفحة فارغة أو لا تظهر المكونات

الحل:

```bash
python3 -m http.server 4173
```

ثم افتح:

```text
http://127.0.0.1:4173
```

ولا تفتح `index.html` عبر `file://`.

### المشكلة: رسالة تعذر تحميل components.json

تحقق من:

- أنك داخل جذر المشروع.
- أن `components.json` موجود.
- أن الخادم يعمل من نفس المجلد.
- أن JSON صالح.

### المشكلة: الطرف غير معروف

تحقق من:

```text
componentId.pinName
```

ثم ابحث عن:

- component ID في `components`.
- pin name في `components.json`.

### المشكلة: JSON لا يرسم

تحقق من:

- فاصلة مفقودة.
- قوس غير مغلق.
- `components` ليست مصفوفة.
- `wires` ليست مصفوفة.
- وجود IDs مكررة.
- وجود endpoint غير موجود.

### المشكلة: المكوّن المخصص لا يظهر بعد إعادة فتح الموقع

المكونات المخصصة محفوظة في Local Storage للمتصفح. قد تختفي إذا:

- حذفت بيانات الموقع.
- استخدمت متصفحًا آخر.
- استخدمت نافذة خاصة.
- غيّرت Origin أو النطاق.

لذلك احتفظ بملف JSON الأصلي للمكوّن.

### المشكلة: PDF لا يبدو كصفحة هندسية

التصدير الحالي يعتمد على Print CSS في المتصفح. جرّب:

- Landscape.
- Margins: None أو Minimum.
- Background graphics.
- Scale مناسب.

### المشكلة: المحرك يدور بالعكس

هذا قد يكون بسبب:

- تبديل `M+` و`M-`.
- تركيب المحرك على الجانب المقابل.
- قيمة `REVERSE_MOTOR_DIRECTION`.
- اتجاه IN1/IN2.

### المشكلة: ESP32 يعيد التشغيل

تحقق من:

- مصدر الطاقة.
- تيار L298N المنظم.
- توصيل VIN و3V3.
- عدم تغذية GPIO بجهد أعلى من المسموح.
- أرضي مشترك.
- تيار المحركات وضوضائها.

## 32. الأمان والحدود الكهربائية

هذا المشروع يتعامل مع:

- بطارية 3S قد تصل إلى 12.6V.
- محركات ذات تيار بدء عالٍ.
- إشارات Arduino 5V.
- منطق ESP32 3.3V.
- Driver محركات.
- مكثفات مستقطبة.

3. اقرأ Datasheet للمكون الحقيقي.
4. تحقق من إصدار L298N.
5. تحقق من Jumper المنظم.
6. لا توصل 12.6V إلى ESP32.
7. لا توصل 5V إلى ESP32 `3V3`.
8. استخدم Level Shifter في خط Arduino TX إلى ESP32 RX.
9. استخدم Voltage Divider لـHC-SR04 Echo مع ESP32.
10. لا توصل محركًا مباشرة إلى GPIO.
11. ضع مقاومات LEDs.
12. تحقق من قطبية المكثف.
13. اختبر المحركات والعجلات مرفوعة.
14. استخدم حماية مناسبة للبطارية 3S.
15. لا تعتبر نجاح فحص الموقع شهادة أمان.

## 36. الأسئلة المتكررة

### هل أستطيع توصيل Arduino وESP32 فعليًا من خلال الموقع؟

الموقع ينشئ تمثيلًا للاتصال ويصدر بياناته، لكنه لا يوصل الأسلاك فعليًا ولا يتحكم في جهازك تلقائيًا.

### هل الموقع يعرف أن الجهد خطير؟

يعرض بعض التحذيرات والبيانات الموثقة، لكنه لا يقيس الدائرة ولا يضمن السلامة.

### هل أستطيع تشغيل Firmware داخل الموقع؟

لا حاليًا. Firmware موجود كملفات مصدر للرفع إلى اللوحات الحقيقية.

### هل يمكن إضافة Wheel أو Motor جديد؟

نعم، يمكن إضافة مكوّن مخصص بملف JSON. لكنه لا يحصل تلقائيًا على نموذج فيزيائي.

### هل يمكن إضافة مقاومة أو Diode؟

نعم. توجد مقاومات ودايودات ومكونات حماية في المكتبة الحالية.

### هل يمكن تصدير PDF؟

نعم، عن طريق نافذة الطباعة في المتصفح.

### هل يمكن تصدير Gerber؟

لا. الرسم الحالي ليس PCB layout.

### هل البيانات محفوظة في قاعدة بيانات؟

لا. المشروع ثابت، والحفظ يتم بتنزيل JSON أو عبر GitHub عند تحديث الملفات.

### هل المكونات المخصصة تظهر لكل المستخدمين؟

لا تلقائيًا. تحفظ محليًا في متصفح المستخدم ما لم تُضاف إلى ملفات المشروع وتُرفع إلى GitHub.

### هل Wokwi أفضل لهذا النوع من المحاكاة؟

إذا كان الهدف تشغيل Firmware ومحاكاة MCU، فمحاكي متخصص مثل Wokwi أنسب. إذا كان الهدف توثيق توصيلات BalanceBot بأسماء أطراف مخصصة وملفات JSON محلية وFirmware مرتبط بالمشروع، فهذا الموقع يوفر طبقة متخصصة لذلك.

### هل يمكن اعتبار الرسم مخططًا كهربائيًا نهائيًا؟

لا. هو Wiring Diagram منظم ومراجع منطقيًا، وليس بديلًا عن schematic هندسي كامل أو PCB CAD.

# ملحق: تنفيذ النواة الرقمية — المرحلة 0 والمرحلة 1

## نطاق هذا التنفيذ

تمت إضافة أول طبقة تشغيل فعلية من معمارية المحاكي الهجين، مع إبقاء المحرر الحالي وملفات التوصيلات السابقة كما هي. هذه الطبقة ليست بعد محرك CircuitJS أو Matter.js؛ إنها نواة رقمية مستقلة تمهّد لهما.

### الهيكلة الجديدة

```text
simulation/
├── README.md
├── main.js
├── digital-core.js
├── monaco-editor.js
├── compile-service.js
├── intel-hex.js
├── avr8js-runner.js
└── default-sketch.js

compiler-service/
├── server.mjs
├── package.json
├── Dockerfile
└── README.md
```

### Monaco Editor

يحاول الموقع تحميل Monaco Editor من CDN رسمي عند فتح لوحة النواة الرقمية. إذا نجح التحميل تظهر واجهة Monaco مع تلوين C++، وإكمال تلقائي أساسي، وتغيير حجم تلقائي. إذا لم يتوفر CDN أو فشل الاتصال، يعود الموقع إلى محرر `textarea` مدمج حتى لا تتعطل الواجهة الحالية.

### دورة التجميع

زر `تجميع + تحميل AVR` يرسل المصدر إلى:

```text
POST /api/compile
```

بصيغة:

```json
{
  "board": "arduino:avr:uno",
  "code": "... Arduino source ..."
}
```

الاستجابة المتوقعة:

```json
{
  "ok": true,
  "board": "arduino:avr:uno",
  "hex": ":10000000...",
  "diagnostics": ""
}
```

### خدمة Arduino CLI

الملف `compiler-service/server.mjs` يوفر endpoint اختياريًا. يكتب المصدر في مجلد مؤقت، ويشغل `arduino-cli compile` على لوحة Uno، ويعيد ملف Intel HEX، ثم يحذف المجلد المؤقت. توجد أيضًا `Dockerfile` لتشغيل الخدمة في حاوية منفصلة.

الخدمة لا تُضمّن تلقائيًا في الموقع الثابت؛ يجب تشغيلها في بيئة تملك Arduino CLI ثم توجيه `data-compile-endpoint` في HTML أو إعداد proxy مناسب. هذا الفصل مقصود حتى لا تُمنح صفحة عامة صلاحية تشغيل مترجم على الخادم بلا عزل.

### Intel HEX

الملف `simulation/intel-hex.js` يطبق:

- فحص بداية كل سجل.
- فحص طول السجل.
- فحص byte count.
- فحص checksum.
- دعم سجلات البيانات.
- دعم extended segment address.
- دعم extended linear address.
- فحص EOF.
- تحويل البايتات إلى كلمات AVR little-endian.
- منع تجاوز حجم Flash المحدد.

### avr8js

الملف `simulation/avr8js-runner.js` يحمّل avr8js كـES Module عند الحاجة، ثم:

1. ينشئ Flash بحجم ATmega328P.
2. ينشئ CPU افتراضيًا.
3. يربط Port B وPort C وPort D.
4. يراقب تغيرات المنافذ.
5. يحول بتات المنافذ إلى أرقام Arduino الرقمية.
6. ينفذ عددًا محدودًا من الدورات في كل خطوة.
7. يوفر تشغيلًا مستمرًا عبر `requestAnimationFrame`.
8. يوفر إيقافًا مؤقتًا وخطوة منفردة.

خريطة المراقبة:

```text
PORTD bit 0..7 → Arduino pins 0..7
PORTB bit 0..5 → Arduino pins 8..13
PORTC bit 0..5 → Arduino pins 14..19 / A0..A5
```

### معنى GPIO في المرحلة 1

في هذه المرحلة يتم عرض حالات GPIO الرقمية الناتجة من CPU الافتراضي. لا توجد بعد شبكة كهربائية تربط تلك الحالات بمكثف أو L298N أو محرك.

لذلك فإن `HIGH` و`LOW` هما نتيجة رقمية للبرنامج، وليسا جهدًا مقاسًا من دائرة تناظرية.

### ما تم تنفيذه فعليًا

- دمج لوحة Digital Core داخل الموقع الحالي.
- تحميل Monaco أو استخدام fallback.
- محرر Arduino افتراضي.
- إرسال مصدر الكود إلى compile endpoint.
- تحليل Intel HEX.
- تحميل avr8js عند التشغيل.
- مراقبة Ports B/C/D.
- تشغيل CPU على دفعات محدودة.
- عرض سجل الأحداث وحالات GPIO.
- خدمة Arduino CLI اختيارية مع Docker.
- فحوصات Node وPython للمصادر الحالية.

### ما لم يُنفذ في المرحلة 1

- لا يوجد CircuitJS أو SPICE.
- لا توجد معادلة مكثف مربوطة بحالة GPIO.
- لا يوجد حقن ADC من دائرة تناظرية.
- لا يوجد نموذج L298N تناظري.
- لا يوجد نموذج محرك أو عزم.
- لا يوجد QEMU/ESP32 emulator.
- لا توجد مكونات `wokwi-elements` الواقعية بعد.
- لا يوجد Matter.js.
- لا يوجد بناء Arduino داخل الموقع المنشور ما لم تُشغّل خدمة compile منفصلة.

هذه الحدود مقصودة حتى تبقى كل مرحلة قابلة للتحقق بدل تقديم زر محاكاة يوحي بقدرات غير موجودة.

# ملحق: المرحلة الثانية — الواجهة والمكونات التفاعلية

تمت إضافة طبقة المرحلة الثانية دون حذف النواة الرقمية أو محرر التوصيلات السابق.

## الملفات الجديدة

- `simulation/orthogonal-router.js`
- `simulation/interactive-components.js`
- لوحة `INTERACTIVE COMPONENTS · PHASE 2` داخل الواجهة.
- حدث `balancebot-diagram-rendered` بين renderer وطبقة التفاعل.
- حدث `balancebot-component-change` لعرض تغييرات المستخدم.

## A* Orthogonal Router

يستخدم مسار الأسلاك شبكة متعامدة وخوارزمية بحث A* مبسطة:

1. تقسيم مساحة الرسم إلى خلايا 24px.
2. استبعاد مستطيلات المكونات مع padding قدره 18px.
3. السماح بحركة أعلى/أسفل/يمين/يسار فقط.
4. تقييم المسار حسب المسافة.
5. منع المرور داخل المكونات الأخرى.
6. إعادة مسار متعامد بسيط إذا تعذر إيجاد مسار شبكي.

المسار يحسن الوضوح البصري، لكنه ليس DRC كهربائيًا.

## المكونات التفاعلية

- LED: نقر للتبديل بين ON/OFF مع إضاءة CSS.
- TT Motor: نقر للتبديل بين متوقف وPWM تجريبي مع دوران بصري.
- Potentiometer: شريط منزلق من 0 إلى 1023 يمثل WIPER.
- HC-SR04: شريط مسافة من 2 إلى 400cm يمثل ECHO افتراضيًا.

القيم الحالية تفاعلية داخل الواجهة وليست قياسات كهربائية حقيقية.

## Wokwi Elements وFallback

يحاول `interactive-components.js` تحميل `wokwi-elements` من CDN اختياريًا. إذا نجح يظهر runtime الخارجي، وإذا فشل CDN يستخدم الموقع Web Components محلية باسم `balancebot-*` حتى تبقى الواجهة قابلة للتشغيل.

هذه طبقة Wokwi-style مع adapter اختياري، وليست ادعاءً بأن كل مكونات Wokwi أصبحت محاكية كهربائيًا.

## حدود المرحلة الثانية

لم يتم بعد تنفيذ CircuitJS/SPICE، معادلات المكثفات، حقن ADC الحقيقي، نموذج L298N التناظري، Matter.js، ESP32 emulator، أو تشغيل محرك حقيقي وفق PWM. هذه عناصر المرحلتين الثالثة والرابعة.

## اختبار Compiler Service

تم اختبار المسار كاملًا باستخدام Arduino CLI ومنصة `arduino:avr`:

```text
POST /api/compile
board: arduino:avr:uno
result: ok=true
artifact: Intel HEX
hex length: 2611 characters
EOF record: present
```

كود الاختبار استخدم `pinMode`, `digitalWrite`, و`delay` على LED في pin 13. تم إصلاح بنية sketch، البحث التكراري عن HEX داخل build، وجعل `ARDUINO_DIRECTORIES_DATA` قابلًا للتهيئة.

# ملحق: المرحلة الثالثة — المحرك التناظري وMatter.js

تمت إضافة طبقة محاكاة هجينة مبسطة داخل `simulation/`:

- `analog-engine.js`: نموذج البطارية 3S، مكثف التنعيم، هبوط L298N، جهد المحرك، RPM، والتيار.
- `physics-world.js`: تحميل Matter.js من CDN وإنشاء chassis وعجلتين ومحرك فيزيائي ثنائي الأبعاد.
- `hybrid-engine.js`: يربط PWM اليسار واليمين بالنموذج التناظري ثم يرسل جهد المحركات إلى Matter.js.

## عناصر التحكم

- `تشغيل الفيزياء`: تحميل Matter.js وبدء Runner.
- `إيقاف`: إيقاف حلقة التحديث.
- `إعادة ضبط`: إعادة المكثف والمحركات ووضع الروبوت.
- PWM يسار/يمين: من -255 إلى +255 للتحكم في الاتجاه والسرعة.

## القياسات المعروضة

- جهد التغذية.
- جهد المكثف.
- RPM للمحرك الأيسر والأيمن.
- التيار الكلي التقريبي.
- حالة Matter.js.

## حدود الدقة

هذه ليست بعد محاكاة SPICE أو نموذجًا كهربائيًا مصنعياً لـL298N. المعادلات الحالية تعليمية ومبسطة: هبوط ثابت تقريبي، RPM خطي مع الجهد، وتيار تقريبي مع duty cycle. Matter.js يحاكي الحركة ثنائية الأبعاد وليس اتزان روبوت حقيقيًا مع IMU بعد.

## نشر الأصول في الموقع الثابت

بعض مسارات الملفات الفرعية لا تُخدم في بيئة النشر الثابتة الحالية، لذلك أصبح `app.js` يحتوي على bundle المتصفح الكامل للنواة الرقمية وA* والمكونات التفاعلية ومحرك Matter.js. تبقى الملفات المنفصلة داخل `simulation/` للمصدر والاختبار، بينما يعتمد الموقع العام على bundle واحد مخدوم من الجذر.
